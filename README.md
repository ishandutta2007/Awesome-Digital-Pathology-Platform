# Awesome-Digital-Pathology-Platform

## Top Digital Pathology Platform Ecosystem



**Curated List of SaaS Products & Open-Source GitHub Projects**  

*Focused on Whole-Slide Imaging, Computational Pathology, AI Diagnostics, Viewer & Analysis Workstations*  

**Last updated: October 2026**



This repository tracks notable **SaaS platforms** and **open-source projects** for **Digital Pathology**. These systems manage whole-slide images (WSI), support primary diagnosis or research, and increasingly apply AI for detection, quantification, and workflow automation.



**Examples** include PathAI, Proscia, Paige, Philips IntelliSite, Indica Labs (HALO), Aiforia, Ibex Medical Analytics, Visiopharm, Gestalt Diagnostics, Inspirata, Leica Aperio, Deep Bio, Hamamatsu NanoZoomer, and Roche Navify Pathology (the category leaders).



**Open-source emphasis**: Research and annotation are strong in open source. **QuPath**, **OpenSlide**, **ASAP**, **Cytomine**, and **OMERO** form a capable open pathology stack. This section is heavily expanded.

## Open-Source GitHub Projects



- **[QuPath](https://github.com/qupath/qupath)**  

  Leading open-source bioimage analysis software for digital pathology—annotation, cell detection, machine learning, and scripting for research and education.



- **[OpenSlide](https://github.com/openslide/openslide)**  

  Foundational open C library for reading multi-vendor whole-slide images—used by almost every open pathology tool.



- **[ASAP (Automated Slide Analysis Platform)](https://github.com/computationalpathologygroup/ASAP)**  

  Open viewer and analysis platform for WSI—annotation, multi-resolution viewing, and Python-friendly processing.



- **[Cytomine](https://github.com/cytomine)**  

  Open-source web platform for collaborative analysis of large-scale biomedical images, including pathology.



- **[OMERO](https://github.com/ome/openmicroscopy)**  

  Open microscopy environment—enterprise-grade image data management used for pathology and life-science imaging.



- **[HistomicsTK / Digital Slide Archive](https://github.com/DigitalSlideArchive)**  

  Open tools for pathology image analysis and web-based slide archives (Kitware ecosystem).



- **[tifffile, scikit-image & WSI Python stacks](https://github.com/cgohlke/tifffile)**  

  Open Python libraries commonly used in computational pathology pipelines.



- **[PathML & deep learning pathology toolkits](https://github.com/search?q=PathML+OR+computational+pathology+deep+learning)**  

  Open frameworks for ML on whole-slide images in research settings.



### Additional Strong Open-Source Options



- **Analysis workstation**: QuPath for interactive annotation and quantitation.

- **I/O layer**: OpenSlide for vendor WSI formats.

- **Web collaboration**: Cytomine or Digital Slide Archive.

- **Data management**: OMERO for large institutional repositories.

- **Composable stacks**: Scanner → OpenSlide/QuPath → Python ML → OMERO/Cytomine for sharing.

- Commercial platforms still lead in IVD-cleared AI, LIS integration, and regulated primary diagnosis.



**Frameworks for building custom systems**:  

**QuPath** + **OpenSlide** are the core open research stack; **ASAP**, **Cytomine**, and **OMERO** extend viewing and collaboration.  

Clinical primary diagnosis and FDA/CE-marked AI typically require commercial platforms (Philips, Paige, PathAI, Proscia, etc.).  

Academic labs often run fully open analysis; clinical labs combine scanners, open tools for research, and validated commercial systems for diagnosis. Fully open digital pathology is excellent for research; regulated clinical use needs validated products.

## Disclaimer



- This is a **community-curated** list — not exhaustive and not an endorsement.

- Clinical digital pathology is regulated. Only use validated, cleared systems for primary diagnosis where required by law. Research tools (including open source) are not substitutes for certified clinical software without proper validation and quality systems.

- Whole-slide images are sensitive patient data—apply HIPAA/GDPR and institutional controls. Open-source tools offer transparency but place validation and security on the operator. Commercial platforms shift regulatory and support burden to the vendor.
